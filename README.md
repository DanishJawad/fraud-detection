# Cost-Optimized Fraud Detection

Credit card fraud is 0.17% of transactions in this dataset. A model optimized for accuracy
just predicts "not fraud" every time and scores 99.83%. This project instead picks a decision
threshold that minimizes expected business cost: a missed fraud (false negative) costs more
than a wrongly blocked legitimate transaction (false positive), so the threshold should reflect
that asymmetry instead of sitting at the default 0.5.

The pipeline is: SMOTE oversampling on the training split only, a RandomForest classifier, a
cost-sensitive threshold sweep, a FastAPI service that serves predictions and takes delayed
ground-truth feedback (the way real fraud labels arrive, via chargebacks), and a monitoring
endpoint that computes detection rate and cost from that feedback as it comes in.

## Results

Trained on the [Kaggle credit card fraud dataset](https://www.kaggle.com/mlg-ulb/creditcardfraud)
(284,807 transactions, 492 fraud, ~0.17%), with a temporal split (train on earlier transactions,
test on later ones, so evaluation matches how the model would actually be used):

| Metric | Value |
|---|---|
| ROC-AUC | 0.977 |
| Fraud detection rate at optimal threshold | 77.3% |
| False alarm rate at optimal threshold | 0.011% |
| Optimal threshold | 0.41 |
| Cost savings vs. no-SMOTE logistic regression baseline | 11.1% |

Cost assumptions: $50 per false positive (manual review), $500 per false negative (missed
fraud) — see `config.yaml`. These are illustrative, not real business figures; changing them
changes the optimal threshold, which is the point of the threshold sweep.

The 11.1% cost-savings figure is a real, reproducible number from a fair baseline (a plain
logistic regression trained without SMOTE, also threshold-optimized), not against the
unoptimized default threshold of 0.5. All numbers above are regenerated by `scripts/train.py`
and written to `models/metadata.json` — nothing here is hand-typed.

## How it works

1. **`scripts/train.py`** — the only source of the shipped model. Loads the raw CSV, splits
   temporally, fits `StandardScaler -> SMOTE -> RandomForestClassifier` as one
   `imblearn.pipeline.Pipeline` (`src/models.py::train_smote_pipeline`). imblearn's Pipeline
   only resamples during `.fit()`, so SMOTE structurally cannot leak into the test split.
   Sweeps thresholds (`src/evaluation.py`) against `config.yaml`'s cost assumptions, saves
   `models/fraud_model.pkl` and `models/metadata.json`.
2. **`app/main.py`** — FastAPI service. Loads the model at startup, serves `/predict` and
   `/predict-batch`, reports `/metrics` from metadata, and takes ground-truth feedback via
   `/feedback` (see below).
3. **`monitoring/tracker.py`** — logs every prediction with a `prediction_id`. When
   `/feedback` reports the real label for that id later, `/monitoring` computes live
   detection rate, false-positive rate, and accumulated cost from whatever's been labeled
   so far, plus a simple drift check on the rolling mean predicted probability.
4. **`dashboard/app.py`** — Streamlit dashboard polling `/health` and `/metrics`.
5. **`Dockerfile`** / **`Dockerfile.dashboard`** / **`docker-compose.yml`** — the API and
   dashboard as two containers.

`notebooks/*.py` are the exploration history that led here (baseline without SMOTE, SMOTE vs.
class-weighting comparison, cost sensitivity analysis) — kept for the record, but
`scripts/train.py` is what actually produces the shipped artifacts now.

## Run it locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

# Download creditcard.csv from Kaggle and place it at data/creditcard.csv, then:
python scripts/train.py

# Terminal 1: API
PYTHONPATH=. uvicorn app.main:app --port 8000

# Terminal 2: dashboard
streamlit run dashboard/app.py
```

Try it:

```bash
curl http://localhost:8000/health
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"features": [0.0, 0.0, ..., 0.0]}'   # 29 values: V1..V28, Amount
```

### Prove the monitoring is real, not wired-but-dead

```bash
python scripts/simulate_traffic.py --n 2000
```

This replays held-out (never-trained-on) transactions through `/predict`, immediately follows
each with `/feedback` carrying the real label (standing in for a delayed chargeback
confirmation), and prints `/monitoring` periodically. Watch the detection rate jump the moment
a real fraud transaction is replayed and correctly flagged — that's the loop actually running
against real traffic, not a metrics endpoint that always returns zeros.

### Docker

```bash
python scripts/train.py   # models/ is gitignored — build it once before compose mounts it
docker compose up --build
# API: http://localhost:8000
# Dashboard: http://localhost:8501
```

### Tests

```bash
PYTHONPATH=. pytest tests/ -v
```

Covers the API endpoints, the SMOTE pipeline (no leakage into held-out data, reproducible given
a fixed seed), the cost-threshold sweep, and the monitoring feedback loop.

## Known limitations

- Feedback labels update the monitor's in-memory log only. They're not replayed back into the
  JSONL file on restart, so `/monitoring` resets on every process restart. Fixing this properly
  means using the Postgres path already scaffolded in `monitoring/db.py` instead of a
  rewrite-on-every-label approach to a flat file.
- `ab_test/framework.py` and `retrain/pipeline.py` are real, working scaffolding but nothing
  currently calls either of them — no scheduler, no CLI wired up. Next step if this needed to
  actually retrain in production: a cron job or scheduled task calling `retrain/pipeline.py`
  when `should_retrain()` returns true.
- The RandomForest + SMOTE combination beats a plain logistic regression baseline by 11.1% on
  cost, not the much larger number an earlier, unreproducible version of this repo claimed.
  I'm keeping the honest number.
